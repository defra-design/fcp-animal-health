Back office access

There are 2 types of back office user. Each has a set of the RPA’s role-based access control (RBAC) roles. A case officer can request some things, such as withdrawing a claim, and a team lead approves or rejects the request. No one can approve their own request.

{{ govukTable({ caption: "Types of back office user", captionClasses: "govuk-table__caption--m", head: [{ text: "Type" }, { text: "RPA roles" }, { text: "Personas" }], rows: typeRows }) }} {{ govukTable({ caption: "What each type of user can do", captionClasses: "govuk-table__caption--m", head: [ { text: "Action" }, { text: "Case officer" }, { text: "Team lead" }, { text: "RPA roles that can do it today" }, { text: "Notes" } ], rows: permissionRows }) }}

“Request” means they can ask, and a team lead approves or rejects it. What a case officer and team lead can do is based on the RPA’s roles table and the authorisation workflow. Where it goes beyond the RPA’s table, it is our proposal, to agree with the RPA.
